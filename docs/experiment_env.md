# Experimental environments

**Start with MiniGrid KeyCorridor for diagnostics and use Craftax-Classic Symbolic for the first main experiment.** The scientific requirements are partial observation, consequential alternative actions, a terminal objective, repeatable decisions and enough successful continuations to estimate differences. These are distinct from simulation throughput. Measure both rollout cost and the fraction of informative decisions in the pilot.

| Environment | Role and rationale | Adaptation or limitation |
| --- | --- | --- |
| MiniGrid BabyAI KeyCorridor | A key in one room opens a locked door guarding the target. The dependency makes failed waypoint execution easy to inspect. | Keep the partial observation. Define binary terminal success explicitly. Random layouts test generalization. Add the stochastic-action wrapper only in a separately labeled test of transition randomness. [Task](https://minigrid.farama.org/environments/babyai/KeyCorridor/) · [Wrapper](https://minigrid.farama.org/api/wrappers/#stochastic-action) |
| Craftax-Classic Symbolic | A JAX reimplementation of Crafter with resources, inventory, survival and crafting dependencies. The transition takes a state, action and PRNG key, which supports repeated attempts from the same simulator state. | Use the official Classic symbolic variant and keep the complete simulation state private. Define a terminal predicate such as first creation of an iron pickaxe. Score the terminal transition before any automatic reset. Record default achievements for diagnostics and specify any reward given to the policy. [Paper](https://proceedings.mlr.press/v235/matthews24a.html) · [Environment implementation](https://github.com/MichaelTMatthews/Craftax/blob/main/craftax/craftax_classic/envs/craftax_symbolic_env.py) |
| Original Crafter | Direct precedent for Director’s learned latent goals. Its public examples show goals involving tools, resources and shelter. | Useful for closer comparison to published pixel-based agents. Symbolic observations, terminal-only rewards and different simulator versions each change the comparison. Re-run baselines on the chosen setup. [Director](https://danijar.com/project/director/) · [Crafter](https://github.com/danijar/crafter) |
| OGBench AntMaze Teleport | Stochastic destinations make it possible to test optimistic estimates of route quality on a second benchmark with offline data. | Validate reset, state restoration and evaluation goals before promising action-branch labels. Charge any additional online attempts separately in offline comparisons. [OGBench](https://seohong.me/projects/ogbench/) |
| Push-T and Diverse Maze | HWM studies how multi-timescale latent predictions support visual control and navigation. These tasks offer a comparison to hierarchical predictive planning. | Use published start–goal and compute protocols for replication. Training from images adds a perception variable. [HWM](https://arxiv.org/abs/2604.03208) |
| Balatro | Later domain for growing decks, ordered Joker effects, economy and hidden draws. | Integrate through the public adapter once the simulator supports the agreed rules, observable actions and branch audit. Measure ranking and win rate on held-out worlds. |
| Minecraft | Dreamer studies long-horizon diamond collection and Voyager builds reusable programs through a Minecraft interaction API. | Useful for a later skill-composition study. Account for differences in action abstraction, observation access and collection cost before comparing results. [DreamerV3](https://arxiv.org/html/2301.04104) · [Voyager](https://voyager.minedojo.org/) |

For Craftax, repeating a single snapshot with fresh random keys estimates variation in the future **conditional on that hidden world**. Estimating what an agent should expect from its observation history also requires averaging over plausible hidden worlds. Initially report the snapshot-conditioned estimate and average over held-out worlds. Introduce history-conditioned resampling only when the sampling assumptions can be tested.
