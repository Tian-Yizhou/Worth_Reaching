# Implementation plan

Start with one rules version, a frozen observation contract, a finite episode budget and a terminal success predicate. The first complete deliverable is a controlled comparison of fixed latent neighborhoods and learned regions in Craftax-Classic. Then test discovery of reliable regions with low demonstration support and performance on the distant terminal objective.

| Milestone | Work | Completion evidence |
| --- | --- | --- |
| 1. Validate the measurement | Implement the smallest environment and evaluation interfaces in the [architecture](docs/architecture.md). Exercise them on MiniGrid KeyCorridor. Record and replay a prefix, force two distinct legal decisions, and score success under a fixed continuation policy. | Replaying a seed and action sequence reproduces observations and termination on the pinned version. A hand-checkable layout distinguishes a helpful action from one that wastes the remaining budget. A hidden-state-only change cannot alter the policy input when public history is identical. |
| 2. Establish the main task | Add Craftax-Classic Symbolic. Wrap the iron-pickaxe achievement as a terminal objective. Define timeout, death, and the exact step on which success is scored. Record complete trajectories from random, scripted and learned policies as available. Count data by source and success. | A known successful trace and a failed or truncated trace produce the expected labels. Repeated branches from a snapshot agree with ordinary rollouts under the same keys. Independent keys produce the intended variation. Freeze a split manifest by original world and episode. |
| 3. Test decision-relevant compression | Train a public-history encoder and short-horizon dynamics. Compare reconstruction, latent prediction, and latent prediction plus action-ranking supervision. Include direct return regression on the same branch labels. | On held-out decisions, report action regret, ambiguous pair frequency, reference uncertainty and model cost. Validate local control on actually reached waypoints. If almost every branch fails, shorten the pilot objective or stratify starting histories and retain the original full-task evaluation. |
| 4. Test regions and candidate scoring | Compare fixed-radius latent targets with outcome-informed regions at comparable coverage. Fit a factorized value filter and a scorer of terminal success after attempting a region on shared branch data. Freeze a reference catalogue and estimate demonstration support. | On independent continuations, report within-region variation, arrival, terminal success and scorer disagreements. Report how often reliable regions are found and selected in each support bin. |
| 5. Test long-horizon planning | Compare flat planning, designer milestones, fixed neighborhoods and learned regions. Benchmark replay as a proposer, then compare conditional diffusion or flow matching with coarse predictions from a hierarchical world model. | Terminal success on held-out worlds at comparable inference and interaction budgets, with viable candidate diversity and counts of alternative regions per decision. |
| 6. Improve the proposer | Warm-start online RL from the best tested flow proposer. Compare Flow-GRPO with the pretrained proposer plus reranking when the pilot has enough informative returns. | Terminal success and discovery of reliable low-support regions on independent evaluation trajectories. Record groups with tied returns, generation cost and every environment step used for tuning. |
| 7. Test goal transfer | Keep the rules and observations fixed. Withhold a second terminal predicate, such as crafting the same tool with a health reserve. Compare frozen dynamics, fitting a goal head, and full adaptation with equal new-goal data. | Report base- and new-goal success together. A separate environment or altered mechanics can later test dynamics shift. |

## Pilot decisions

Begin the branch pilot with roughly 100 independent decision histories, two or three applicable actions per history and 16 continuations per action. These are starting estimates for measuring runtime, outcome variance and coverage. Use development results to set the definitive branch count, number of worlds and independent training seeds. Freeze the test protocol before comparing final policies. Log simulator interactions for branch supervision as well as ordinary training. Annotate privileged resets and compare against equally reset-enabled methods.

If the frozen controller struggles with waypoints taken from successful trajectories, examine the goal encoding, deadline and execution budget before fitting a more elaborate high-level selector. If the controller can reach proposed waypoints but terminal success stays flat, compare their downstream value under the same continuation policy. If outcomes are sensitive to one training seed or a few maps, report that uncertainty before extending to a second domain.

## Exploratory energy-guided planning

After the shared-candidate comparison, test whether a learned energy can improve which waypoints the generator proposes. Use negative log success probability as a reference and compare energy-guided generation with reranking under the same proposal and interaction budgets.

## Later environments

OGBench teleport mazes can test whether rare favorable outcomes distort reachability estimates. Balatro can test variable entity counts and strategic purchases when its observation and branch interfaces are validated. Each extension gets its own protocol version and comparison, as described in [environment choices](docs/experiment_env.md).
